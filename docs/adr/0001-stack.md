# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-10-11
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

The PRD (v0.1.0, approved) describes a turn-based quiz game with a handful of screens and no real-time rendering:

- Rendering: standard React Native Views (text, large buttons, a scrollable list of ~150 animals, emoji).
  Animations are minimal (fade, small bounce): React Native `Animated` or Reanimated 4 is enough; no Skia.
- Audio: ~220 bundled MP3 files (questions, proposals, fixed sentences) and 2 sound effects, played offline,
  stopped on answer, replayable → `expo-audio` (`useAudioPlayer` / `createAudioPlayer`, `seekTo(0)` + `play()`).
- Haptics: short vibration on victory / give-up → `expo-haptics`.
- Storage: consent and 3 settings, local only → the factory overlay's local storage.
- App lifecycle: resume the current game after background → React Native `AppState` (core), no native code.
- Telemetry: opt-in Firebase Analytics + Crashlytics → `@react-native-firebase/app` and `/crashlytics` config plugins.
- Data and audio generation (CSV → TypeScript, edge-tts → MP3) are local scripts outside the app runtime:
  no native impact.
- Build: local Gradle on Windows, signed arm64 APK sideloaded; no EAS, no cloud build.
- Permissions: no microphone, no AD_ID (blocked in `app.config.js`).

No custom native module, no sensor, no library outside the Expo SDK or React Native Firebase.

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes | yes | expo-audio, expo-haptics are Expo modules; RN Firebase ships config plugins |
| Need to hand-edit native Android code continuously | high | no need | no need | nothing native in the PRD |
| Custom native module (Kotlin/C++) needed | medium | no | no | |
| Upgrade effort over time | medium | low (bump SDK, `expo install --fix`) | higher (Upgrade Helper, native diffs) | |
| Build simplicity on this machine (local Gradle) | medium | prebuild + Gradle via `build-apk.mjs` | Gradle via `build-apk.mjs` | equivalent |
| Firebase setup effort | low | config plugins | manual Gradle setup | |
| Bundling ~220 audio assets | medium | Metro assets (`require`) + expo-audio | Metro assets + a third-party audio lib | ~3 MB, fine either way |

## Decision

Expo with Continuous Native Generation (SDK 57, React Native 0.86, New Architecture), built locally with
`npx expo prebuild` and Gradle. Rendering with React Native Views; animations with `Animated` (or Reanimated if the
overlay already ships it). Reasons:

1. Every need of the PRD is covered by Expo modules (`expo-audio`, `expo-haptics`) and RN Firebase config plugins:
   none of the 3 criteria forcing bare applies.
2. Lower upgrade and maintenance cost: `android/` is generated, upgrades are an SDK bump.
3. It is the factory default, so scaffold, build and verify scripts are the most proven path.

## Consequences

- Easy: adding Expo modules with `npx expo install`, upgrades, Firebase through plugins.
- Harder: any future native tweak must go through a config plugin (`plugins/`, `app.config.js`).
- `android/` is generated by `npx expo prebuild` and git-ignored.
- Audio files are bundled as static `require()` assets through a generated manifest (one entry per sentence), so a
  missing file fails the tests (PRD AC-13).
- The build expects JDK 17 (factory pinned version); this machine reports Java 25: to check during scaffold.

## Alternatives considered

- Bare React Native: full control of `android/`, but no need for it here and higher upgrade cost.
- Skia rendering: unnecessary for a text-and-buttons game.
- On-device TTS (`expo-speech`): rejected by the brief in favour of pre-generated neural voice files.
